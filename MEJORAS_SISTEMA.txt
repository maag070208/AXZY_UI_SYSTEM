RESUMEN DE ESTA REVISIÓN (2026-09-10)
================================================================================

Se auditaron los 52 componentes buscando (a) mejoras generales y (b) inconsistencias
en el uso del propio UI system (theme.ts, utils/styles.ts, ITThemeProvider). Se
aplicaron los fixes de mayor impacto/menor riesgo; los de mayor alcance (extracción
completa de ITTable/ITDataTable, alineación total de sidebar.tsx al theme, etc.)
quedan documentados abajo como roadmap para una siguiente pasada dedicada.

No se pudo ejecutar `pnpm build` / `pnpm dev` / `pnpm storybook` en el entorno de
este agente (usa un sandbox Linux que no tiene los binarios nativos de Rollup/
esbuild/Tailwind-oxide compilados para esa plataforma — el proyecto los tiene
instalados para macOS arm64). Todo se verificó con `npx tsc --noEmit` (pasa limpio)
y `npx eslint` (mismos warnings/errores pre-existentes, ninguno introducido).
**Antes de publicar una nueva versión, correr `pnpm build` localmente** para
regenerar `dist/` (dist/index.d.ts necesita el rebuild para reflejar todo el JSDoc
nuevo, y dist/index.css necesita el rebuild para reflejar el fix de @theme).

--------------------------------------------------------------------------------
🔴 BUG CRÍTICO ENCONTRADO Y CORREGIDO: falta `@theme` en src/index.css
--------------------------------------------------------------------------------
Las variables `--color-primary-50..950` (y secondary/success/danger/warning/
purple/info) y `--animate-fadeIn` estaban declaradas en un bloque `:root, :host {}`
plano en vez de `@theme { }`. Tailwind v4 SOLO genera utilidades (`bg-primary-100`,
`text-danger-800`, `animate-fadeIn`, etc.) a partir de tokens declarados dentro de
`@theme` — un `:root` plano nunca produce esas clases, aunque la variable CSS sí
exista y se pueda usar con `var(--color-primary-500)`.

Resultado: **18 de ~55 componentes** (alert, avatar, calendar, checkbox, dropfile,
data-table, table, fieldRenderer, form-header, progress, radio, search-select,
slider, stat-card, tabs, textarea, theme-provider, triple-filter) usaban clases
`bg-primary-*`, `text-danger-*`, `border-warning-*`, etc. que **nunca se aplicaban
visualmente** (verificado: `dist/index.css` no contenía ninguna regla `.bg-primary-*`
ni `.animate-fadeIn` antes del fix). `animate-fadeIn` tampoco funcionaba en
tabs.tsx, themeProvider.tsx y dropfile.tsx.

Fix aplicado: `src/index.css` línea 8, `:root, :host {` → `@theme {`. Es un cambio
de una línea, sin efectos secundarios (Tailwind sigue emitiendo las mismas
variables en `:root, :host` automáticamente, además de las utilidades). **Requiere
`pnpm build:css` / `pnpm build` para que `dist/index.css` incluya las clases
nuevas** — no se pudo regenerar en este entorno.

✅ Fixes aplicados en esta revisión
--------------------------------------------------------------------------------
1. **@theme fix** (arriba) — src/index.css
2. **Escala de Z-Index centralizada** — nuevo `export const zIndex` documentado en
   theme.ts (navOverlay:40, drawer:50, modal:60, floating:70, toast:80). Aplicado en
   navbar, layout, drawer, dialog, confirm-dialog, date-picker, time-picker,
   popover, tooltip, search-select, sidebar, topbar, toast. Antes, ITToast (z-50)
   podía quedar detrás de ITDialog/ITDatePicker/ITTimePicker (z-[9999]) o de
   ITConfirmDialog (z-[300]) — con la escala nueva, Toast siempre gana.
3. **ITTable / ITDataTable** ahora usan los helpers ya existentes en
   `utils/styles.ts` (tableContainer, tableHeaderRow, tableHeaderCell, tableBody,
   tableRow, tableCell, tableActionsCell, tableCellText, tableEmptyContent) en vez
   de repetir las mismas clases Tailwind crudas en cada archivo. También se cambió
   `text-red-500`/`text-green-500` (colores Tailwind genéricos) por
   `text-danger-500`/`text-success-500` (la paleta semántica real de la librería,
   ahora funcional gracias al fix de @theme) en el ícono booleano y el mensaje de
   error de catálogo.
4. **select.tsx** ahora usa `inputLabel()` / `inputError` de `utils/styles.ts`,
   igual que input.tsx y textarea.tsx (antes duplicaba sus propias clases).
5. **sidebar.tsx**: 6 valores hex hardcodeados que coincidían exactamente con
   tokens de `theme.ts` (`--color-secondary-50/100/200/400/500/600/900`, 16
   ocurrencias) ahora referencian el token en vez de repetir el literal — mismo
   resultado visual, pero ya no puede quedar desincronizado si cambia la paleta.
6. **search-select.tsx**: 3 fallbacks hex corregidos para coincidir con los
   valores reales de `theme.ts` → `theme.input` (uno de ellos estaba mal — usaba
   `secondary-200` donde `theme.ts` define `secondary-300` para el borde normal).
7. **dropfile.tsx**: se revirtió el badge de estado (Pendiente/Subiendo/Subido/
   Error), que en un cambio sin commitear había pasado de clases con tema
   (`bg-warning-100 text-warning-800 border-warning-200`) a colores hex fijos
   (`#fffbeb`, `#92400e`...). Con el fix de @theme, las clases con tema ya
   funcionan correctamente, así que se restauraron (se mantuvo el resto del
   cambio en curso: migración de `<button>` nativo a `<ITButton>`).
8. **JSDoc completado** para autocomplete/IntelliSense en los interfaces que
   estaban incompletos: `ITThemePalette` (era 3/21 props documentadas → 21/21),
   `Column<T>` / `CatalogOption` (tablas), `FieldConfigV2` / `FieldConfig` /
   `FieldContextV2` (form builder — antes sin ningún JSDoc), `ITDataTableFetchParams`
   / `ITDataTableResponse`, `Step` (stepper).
9. Snippets de VS Code (`snippets/axzy-ui-system.code-snippets`, agregado a
   `files` en package.json) + guía `AUTOCOMPLETE_SETUP.md`.

ROADMAP — pendiente para una próxima pasada más profunda
================================================================================

## 1. Arquitectura de Tipos (Consistencia)
- **Estado**: Revisado — `ITButton`/`ITBadget` ya usan `variant` (estilo) +
  `color` (semántica) de forma consistente entre sí. No se encontraron
  componentes que mezclen ambos conceptos bajo un solo prop.

## 2. Documentación JSDoc
- **Estado**: ✅ Hecho en esta revisión (ver arriba). Cobertura verificada
  componente por componente — quedan solo props triviales sin documentar
  (menos de 5 en total librería).

## 3. Manejo de Layout y Z-Index
- **Estado**: ✅ Hecho en esta revisión (ver arriba).

## 4. Componentes Atómicos (Tailwind Bloat)
- **Estado**: Parcial. ITTable/ITDataTable/ITSelect ya usan `utils/styles.ts`.
  **Pendiente**: ITTable e ITDataTable siguen siendo ~85% código duplicado
  (helpers de renderizado de celda, tarjeta móvil, botones de vista tabla/tarjeta
  son casi idénticos). Recomendación: extraer un hook/archivo compartido
  (`src/components/table/shared/`) con `renderCellContent`, `renderDefaultCard`,
  `renderFilterInput` parametrizados, e importarlo desde ambos componentes. Es
  una refactorización más grande (requiere pruebas visuales en Storybook/sandbox
  antes de mergear) — no se hizo en esta pasada para evitar romper algo sin poder
  verificarlo visualmente en este entorno.

## 5. Storybook y Testing
- **Estado**: Sin cambios. Sigue pendiente documentar estados Loading/Disabled/
  Error/EmptyState en `.stories.tsx` y configurar tests de accesibilidad (a11y)
  automáticos (el addon `@storybook/addon-a11y` ya está instalado).

## 6. Lógica de Negocio en UI
- **Estado**: Sin cambios. `ITDataTable`/`ITSearchTable` siguen con lógica de
  filtrado acoplada al componente. Ligado al punto 4 — al extraer el código
  compartido, es buen momento para mover la lógica de filtrado a
  `useTableLogic`.

## 7. Performance (Renderizado)
- **Estado**: Sin cambios. `ITFormBuilder` sigue re-renderizando el formulario
  completo en cada tecla — falta `React.memo` en campos individuales.

## 8. (Nuevo) Consolidar el sistema de theming
- Actualmente conviven dos mecanismos de color independientes: la paleta
  semántica estática de `theme.ts`/`index.css` (`primary-50..950`, azul por
  defecto) y la paleta dinámica de `ITThemeProvider` (`palette.primary`, cyan
  por defecto, inyectada como `--color-primary` sin escala numerada + overrides
  `!important` sobre clases Tailwind fijas como `.bg-cyan-400`). No se cruzan en
  ningún punto — cambiar el color desde el FAB del ITThemeProvider no afecta a
  ningún componente que use `bg-primary-500`. Vale la pena decidir si deben
  fusionarse (ideal a mediano plazo) o documentarse explícitamente como dos
  capas separadas para que el equipo sepa cuál usar en cada caso.

================================================================================
REDISEÑO VISUAL "PROFUNDIDAD SUAVE" — 2026-09-11
================================================================================
Pasada completa sobre los ~52 componentes: sombras flotantes con tinte frío,
radios más grandes y consistentes, y limpieza de tokens de color. Verificado
con `tsc -b` (0 errores), `eslint .` (425 problemas preexistentes, 0 nuevos —
comparado con `git stash` antes/después) y `pnpm run build` (dist/index.css
compila con los nuevos valores). Preview visual (antes/después + galería de
componentes reales) publicado como artifact — link en la conversación con
Claude que hizo el cambio.

- `src/index.css`: escala `--shadow-xs/sm/md/lg/xl/2xl` y `--radius-xs..3xl`
  reescritas dentro de `@theme`. Cascada automática a los ~76 usos de
  `shadow-*` y todos los `rounded-*` existentes, sin tocar componentes uno por
  uno.
- `src/theme/theme.ts`: botón/input a `--radius-md` (antes `0.375rem`/
  `0.5rem` fijos); card y modal unificados en `--radius-2xl` (antes `1rem`
  card vs `0.75rem` que usaba `card.tsx` — mismatch resuelto). Los fallback de
  `shadow` de card/modal ahora referencian `var(--shadow-md)`/`var(--shadow-
  lg)`/`var(--shadow-xl)` en vez de repetir la fórmula vieja de Tailwind.
- `src/components/card/card.tsx`: el bug central — una card sin `onClick`
  caía en `boxShadow: "none"` (por eso se veían planas en el screenshot que
  disparó este pedido). Ahora toda card tiene `shadow-sm` de reposo; las
  interactivas suben a `shadow-lg` + `translateY(-2px)` en hover.
- `src/components/sidebar/sidebar.tsx`: resuelto el punto 9 de este mismo
  archivo — 11 fallbacks de `#10b981` (verde) → `var(--color-primary-500)`
  para el acento "activo". `theme.ts` ya documentaba que debía ser
  `primary-500`; el componente simplemente no lo seguía. También resueltos
  los 3 grises ajenos al sistema (`#d1d5db`, `#71717a`, `#111827` → tokens
  `secondary-300/400/900`).
- `src/utils/styles.ts`: `inputContainer`/`inputLabel`/`inputError` pasaron de
  `gray-300`/`red-500`/`red-100` genéricos de Tailwind a los tokens propios
  `secondary`/`danger`.
- 27 archivos más (barrido con regex sobre `border|text|bg|ring|...-{gray,
  red}-NNN` → `-{secondary,danger}-NNN`, solo en componentes reales, no en
  `.stories.tsx`): incluye `avatar.tsx` (glow del avatar suavizado de 0.35 a
  0.25 de opacidad), `topbar.tsx` (de `boxShadow:none` a `shadow-xs`, borde
  aclarado a `rgba(15,23,42,0.06)`, colores de acción destructiva alineados a
  `danger`), `dialog.tsx` (overlay de `bg-black/50` a `bg-slate-900/50`), y
  los selectores CSS-in-JS de `theme-provider/themeProvider.tsx` (se
  actualizaron en el mismo barrido para no perder la correspondencia con las
  clases que ahora emiten los componentes).

Fuera de alcance a propósito: el punto 8 de este archivo (paleta estática de
theme.ts vs. paleta dinámica de ITThemeProvider) sigue sin resolver — es una
decisión de arquitectura, no un ajuste visual.

Nota aparte, no relacionada con este rediseño: `pnpm run storybook` falla al
arrancar — ~30 archivos `*.doc.mdx` que Storybook 10.4.3 no puede parsear
("Could not parse import/exports with acorn"). Preexistente, no tocado.
